# 待团队确认的业务规则与接口决策

以下项目尚未写成正式业务事实。三个样例完全是联调占位，不是01A标准答案。不要通过修改评分权重来补救业务定义缺失。

## 业务定义 由01A和产品经理确认

| ID | 待确认问题 | 为什么影响07A | 当前处理 |
|---|---|---|---|
| B01 | 每条规则的原子命题、稳定ID及完整义务清单 | 决定评分分母和查明语义 | 演示五项，未适配正式01A |
| B02 | 哪些是当前决策必要条件、哪些是程序必查 | 决定是否阻断 | 由上游显式声明，不按来源猜 |
| B03 | 多来源是AND、OR还是证明不同命题 | 决定查明条件 | 由Checker聚合，不把来源自动拆义务 |
| B04 | VIP无专属合同时能否使用范围为STANDARD/BASIC的通用规则 | 决定规则适用与回退 | 不推断回退 |
| B05 | 维护是扣除重叠时长还是触发整单排除；时间重叠怎么算 | 决定标准结论和证据要求 | 样例仅是假设命题，不解释正式规则 |
| B06 | 不存在合同/维护记录需要哪些完整查询回执 | 空页能否支持不存在 | query_sufficient由Checker声明 |
| B07 | 试用/沙箱是否应显式定义永不补偿 | 999999与ALL_EXCEPTIONS可能难以执行 | 不解释特殊数字或通配值 |
| B08 | 合同覆盖、规则优先级、同级冲突和版本替代 | 有效反驳与真实冲突不同 | 不按“旧/新”文字推断冲突 |
| B09 | 事故时间、判定时间、抓取时间及生效边界 | 时效判定标准 | 不做抓取年龄衰减 |
| B10 | 来源系统能证明哪些命题 | 来源权威不等于证明资格 | 不允许高等级来源自动替代 |
| B11 | 减少查询时哪些义务已不影响结论、是否仍必查 | 防止非关键缺口过度阻断或关键项被省略 | 上游给适用性和必要性，并保留理由 |

01A当前字段表与JSON的命名/枚举差异也需要统一，但不要求以本模块的名字覆盖全组模型。适配只做双方明确的字段转换。

## 接口与流程 由02B 03A 04B 08B共同确认

| ID | 需要确认 | 当前草案 |
|---|---|---|
| I01 | 评分投影如何从Checker主模型生成 | snapshot schema 0.1-draft；不传全部原始证据 |
| I02 | 不适用与未知适用性的表示 | NOT_APPLICABLE + null；UNDETERMINED + UNKNOWN |
| I03 | 业务结论与流程状态是否分开 | 三类业务决定 + RUNNING/COMPLETED/ESCALATED |
| I04 | 403、冲突是否无条件升级或仅关键项升级 | 评分报告风险，Loop负责执行团队规则 |
| I05 | 三轮如何计算，分页与重试是否计轮 | 未在评分器中实现轮次上限 |
| I06 | 原始证据与查询回执保存在哪里 | evidence_id和snapshot_id可追溯，存储由上游负责 |
| I07 | 是否允许“已有明确结论，但仍送人工审核” | 首版升级时只接受UNDETERMINED，需此能力再扩展 |
| I08 | 公共字段文件、版本维护和集成负责人 | 尚待项目经理安排 |

## 评分展示参数 由07A提出 产品经理和08B确认

| ID | 当前建议 | 说明 |
|---|---|---|
| S01 | 等权查明比例 | 优先可解释性，不代表不同证据风险相同 |
| S02 | 阻断时最高49分 | 演示上限，非统计结论；硬门槛不依赖该数值 |
| S03 | 名称用“证据充分性” | 明示“不是正确概率” |
| S04 | 输入错误不显示正常分数 | 展示数据错误并清除旧评分，不给伪装的0分 |

## 评估口径 由05A 06B 07A确认

- 每次运行的支持性由独立评审根据实际证据判断；谁维护评审规则及样例？
- 自动成功与正确转人工分别报告，是否还需统一的“流程完成率”？
- 原始世界真值、终局预期和方法实际取得的证据如何关联？
- 相同案例的多次运行如何配对、汇总？如何记录模型/提示/随机种子？
- 工具调用、翻页、重试与费用单位如何计数？缺测和失败如何保存？
- 目标阈值、参数冻结日及真实实验数据集版本如何签认？

## 首次联调需要的最少材料

先要一个完整案例：01A定义命题与预期，02B给补查前后快照，03A给轨迹与停止原因，04B给查询回执，05A确认预期，06B输出一次运行记录，08B展示评分卡。正式文件尚未齐备时仍可先用本模块三个样例并行开发。

本文件不宣称同伴没有进度；这里只列当前工作区尚未获得或团队尚未确认的契约。
