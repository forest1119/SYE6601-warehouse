# 评分逻辑与模块边界

我们要解释当前结论的证据基础。Checker 判断每项证据是否适用以及命题的四态，Loop 决定下一步动作，07A 汇总证据充分性并提示阻断风险。

## 评分分母

上游为当前快照列出全部已建模的相关义务。`APPLICABLE` 和 `UNDETERMINED` 都进入分母。只有上游已经明确证明 `NOT_APPLICABLE` 并说明原因的义务才排除。没有可评分义务时返回 `score=null` 和阻断原因，不给100分。

本模块无法发现上游根本没有列出的义务。这是原型限制，应由01A的完整命题清单、02B展开义务、05A独立案例审查共同控制。不得通过漏报义务提高分数。

## 查明与业务方向

`SUPPORT` 表示有效证据支持当前命题，`REFUTE` 表示有效证据反驳当前命题；两者都可计入查明数。必须附至少一个存在的证据引用，且五项 Checker 校验声明均为 true。

`UNKNOWN`、`CONFLICT` 不计入查明数，并必须带原因码及文字解释。未消解冲突至少有证据引用；不同证据之间是否真正冲突由 Checker 判定，不由评分器以数量推断。

```text
原始分 = 100 × 已查明义务数 / 进入分母的义务数
展示分 = 原始分                        没有阻断
展示分 = min(原始分, blocked_score_cap) 有阻断
```

每个义务等权。不因证据条数更多而加分，也不按来源高低排序。五项校验的通过数作为诊断维度展示，不再次加权，避免同一个问题反复扣分。

## 硬门槛

以下情况阻断：

- 任何义务的适用性尚未判明。
- `required_for_decision=true` 或 `must_verify=true` 的义务仍 UNKNOWN/CONFLICT。
- 没有可评分义务，或上游没有声明任何决策所需/程序必查义务。

非关键、非必查义务未知，会降低查明比例并保留 gap，但不必强制拒答。哪些义务可以归为非关键，必须由01A/02B/03A结合业务依赖确认。评分器不自行短路规则。

403、未翻完页、超时等原因码原样输出；是否立即转人工由 Loop 决定。首版只对影响当前判断的义务执行上述门槛。无关来源的历史失败不能自动阻断当前判断。团队若要求任何403都转人工，应在 Loop 的流程规则中明确。

## 门槛和结论

`gate_passed=true` 只表示输入声明的必要证据门槛通过，不自动产生业务结论。只有 Checker 已给确定结论、门槛通过且流程未升级时，`may_present_definitive_decision` 才为 true。

若 Checker 给确定结论，但同时存在阻断，本模块抛出 ContractError。不要静默将其改成另一结论；交02B/03A定位。对于已升级的快照，首版要求业务决定为 UNDETERMINED。未来若需要“已有决定但仍送人工复核”，应扩展契约。

## 三个讲解句

1. 五项查明，Checker建议补偿：100分，可展示确定结论。
2. 合同明确反驳补偿，五项仍都查明：100分，不建议补偿。
3. 只缺关键合同，其余四项查明：原始80分，展示49分，不能确定。

49是暂定展示约定，既不是概率阈值，也不是业务规则。修改它不会改变门槛布尔值。正式使用前要确认并记录评分版本。

## 时间与来源

本模块不根据 fetched_at 新旧自行惩罚合同，也不让“高等级”来源替代另一种证据。事故时间、生效时间和版本是否适用由 Checker 判断；它必须在原始证据及查询记录中保留判定依据。这里的布尔校验只是该结果的评分投影，不构成额外独立审计。
