# 最小指标口径

离线入口 `evaluate_runs(payload)` 接收 `schema_version` 和 `records`。一条记录表示一个方法的一次运行。无依据回答的判断来自该次运行的独立评审，不来自在线分数，也不是案例固定的一个布尔值。

## 谁提供什么

06B提供case/task/run编号、方法、实际结论、是否升级、执行状态、调用/费用/耗时、实验条件。05A与06B约定独立评审标准，提供assessment。07A只汇总，不更改原始记录。

assessment须包含评审ID、评审人/独立评审器、规则版本、被评审的证据快照ID、预期终局、是否应升级、实际回答有无依据、流程是否合规及理由。这里 `rubric_version` 是评审口径版本；业务规则版本单列。

`assertion_supported`：有确定回答时必须为true/false；没有确定回答时必须为null。它评价的是该次回答实际取得的证据是否支撑该结论。缺合同却碰巧答对仍可为false。不能把 score>=阈值、gate_passed 或被测 Checker 自述直接当作这个独立标签。

`reference_decision`是按已确认评审口径、权限和终局条件应有的决定。用 UNDETERMINED + expected_escalated=true 表示应转人工。底层世界的补偿真值仍由05A单独保留，不要把“真实应该不赔”混同于“在当前证据下允许直接宣布不赔”。

## 指标

| 输出字段 | 分子 / 分母 |
|---|---|
| terminal_accuracy | 运行完成且实际决定与预期一致、升级状态也一致 / 全部有效记录 |
| assertion_accuracy | 上述正确终局中的确定回答 / 全部确定回答 |
| unsupported_answer_rate | 独立评审为无依据的确定回答 / 全部确定回答 |
| automatic_coverage | 确定回答数 / 全部有效记录 |
| automatic_success_rate | 完成、正确、有依据、流程合规的确定回答 / 全部有效记录 |
| escalation_rate | 实际升级数 / 全部有效记录 |
| proper_escalations | 正确且流程合规的升级次数（计数） |
| failed_runs | FAILED运行次数，仍保留在相应分母中 |

本最小版以自动成功率体现自动完成，不把正确转人工也称为自动完成。正确转人工单列，防止用一律拒答或升级刷成绩。

分母为0时value=null，同时保存numerator/denominator。所有分组保存run_ids，方便追踪。缺测费用、调用或耗时用null；报告已测数量和缺测数量，均值只基于已测值，不能当作完整总成本。

## 分组与比较

按照方法、comparison_group、数据集版本、规则版本、权限、执行方式、故障来源、演示标记、费用单位、评审口径版本分组。这样自然遗漏/人工注入不会合并，不同费用单位不会求平均。

首版不自动计算“比另一方法提升多少”。正式比较前由06B提供相同case_id、同一世界状态、同权限、同预算口径的配对运行；还需保存模型/提示配置、随机种子、工具轨迹和完整分页行为。comparison_group是团队声明，程序不能仅凭字符串验证实验公平。

无效记录会导致整批校验失败，不会悄悄从分母消失；修复或单独列明缺失后重跑。FAILED是有效但失败的运行记录，必须带独立评审及已测成本，不能用不完整字段来代替。

## 演示数据

`examples/runs.demo.json`只有两个手写运行：同一案例中，两个方法都回答“不建议补偿”，一条有合同依据，一条碰巧猜对。它展示“正确率相同、无依据率不同”。这些方法没有实际执行，所有记录标SIMULATED与synthetic_demo=true；不能用输出数字证明动态方案优于基线。

当前不实现置信区间、AURC、显著性检验或自动阈值选择。应在获得真实且可比较的运行数据后再扩展，避免最小版复杂化。
