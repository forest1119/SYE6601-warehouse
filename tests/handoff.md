## 与置信度组数据对接说明

本文档旨在说明测试组 B 生成的 60 例真实模型跑测及消融实验数据（详见仓库中的 `experiment_results_60.json`）与置信度成绩单前端渲染的数据映射关系。

### 1. 置信度等级映射规则

前端可根据 JSON 数据中的 `model_status` 字段，将案例映射为不同的置信度等级及 UI 表现：

| `model_status` 字段值 | 置信度等级 | 业务含义 | 前端渲染建议 |
| :--- | :--- | :--- | :--- |
| `SUPPORT` / `REFUTE` | **高置信度** | 证据链完整，模型已得出明确结论，可自动完成。 | 绿色 / 正常状态 |
| `UNKNOWN` | **中置信度** | 存在证据缺口、断点或异常阻断，需补查或转人工复核。 | 黄色 / 警告状态 |
| `CONFLICT` | **低置信度** | 证据之间存在逻辑冲突，系统强制阻断。 | 红色 / 错误状态 |

### 2. 缺口、断点与灰点素材示例

JSON 数据中的 `model_reasoning` 和 `discovered_conditions` 字段记录了模型发现的具体问题，可直接作为前端渲染“置信度成绩单”中缺口/断点提示的素材。

**典型场景示例：**

*   **分页证据未获取完整（断点）**
    *   **案例**：`A-009`
    *   **识别特征**：`model_reasoning` 中包含 `pagination_complete=false`。
    *   **前端提示**：“分页证据未获取完整，需补查翻页”。
*   **系统无对应取证工具（阻断）**
    *   **案例**：`A-060`
    *   **识别特征**：`model_reasoning` 中包含 `NO_REGISTERED_SOURCE`。
    *   **前端提示**：“系统无对应取证工具，流程阻断”。
*   **多源证据冲突（灰点/冲突）**
    *   **案例**：`A-040`
    *   **识别特征**：`model_reasoning` 中指出监控与工单数据矛盾。
    *   **前端提示**：“监控系统与工单系统数据矛盾，需人工裁决”。

### 3. 字段解析建议

*   **诊断评语**：建议直接解析 JSON 中的 `model_reasoning` 字段，将其作为成绩单上的“诊断评语”或“置信度说明”展示给用户。
*   **关键条件标签**：可提取 `discovered_conditions` 数组，作为成绩单上的“已核实关键条件”或“新增依赖”标签进行展示。
